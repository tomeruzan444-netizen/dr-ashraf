# אתר ד״ר אשרף אטמנה - רפואת שיניים ואסתטיקה

אתר סטטי (HTML/CSS/JS טהור), ללא תלויות חיצוניות, ללא framework וללא שלב build חובה.
כל דף נטען כ-HTML מלא - כלומר מרונדר לחלוטין בצד השרת מבחינת מנועי חיפוש, וטוען מהר מאוד.

## 🖼️ התמונות באתר

כל התמונות באתר הן **תמונות אמיתיות** של המרפאה, שעובדו אוטומטית לפורמט web:

| היכן | קובץ | מקור |
|------|-------|-------|
| **תמונת הנושא בדף הבית** | `assets/img/dr-asharaf-cutout-{480,720}.webp` | `תמונת תדמית דר אשרף.webp` - הרקע הוסר, נשארו רק ד״ר אשרף והחלוק הלבן |
| **סקשן אודות** (בית + עמוד אודות) | `assets/img/dr-asharaf-portrait.webp` | `תמונה של דר אשרף.webp`, חתוך ליחס 4:5 |
| **סקשן המרפאה** (דף הבית + עמוד אודות) | `assets/img/clinic.webp` | `תמונת המרפאה.jpeg` - חדר טיפולי השיניים |
| _(לא בשימוש, זמין להחלפה)_ | `assets/img/clinic-esthetics.webp` | `קליניקה.webp` - חדר הטיפולים האסתטיים |
| **גלריית לפני/אחרי** | `assets/img/results/case-NN-{before,after}.webp` | 11 המקרים מהתיקייה `תמונות לפני ואחרי` |
| **תמונת שיתוף ברשתות** | `assets/img/og-image.jpg` | לוגו + תמונת ד״ר אשרף על רקע המותג |

הקבצים המקוריים נשארו במקומם בתיקיות `assets/img/תמונות לפני ואחרי/` ו-`assets/img/תמונות של דר אשרף/`.
אפשר למחוק אותן מהעלאה לשרת - הן לא בשימוש באתר עצמו.

### הוספת מקרי לפני/אחרי חדשים

1. שמרו את התמונה החדשה בתיקייה `assets/img/תמונות לפני ואחרי/`
   (קובץ אחד שמכיל **לפני משמאל ואחרי מימין**, עם קו מפריד לבן - בדיוק כמו הקיימות),
   בשם שמכיל את מספר המקרה, למשל `מקרה 13 לפני ואחרי.png`.
2. הריצו:
   ```bash
   cd _build
   python process-images.py
   ```
   הסקריפט מזהה לבד את הקו המפריד, חותך לשניים, מיישר ליחס 4:5, מקטין וממיר ל-WebP.
3. הוסיפו כרטיס חדש ב-`index.html` (העתיקו בלוק `<figure class="ba">` קיים ושנו את המספר והכיתוב).

> דרישות לסקריפט: `pip install pillow numpy`

## 📬 טופס יצירת הקשר

כברירת מחדל הטופס **פותח את תוכנת הדוא״ל של המבקר** עם הפנייה ממולאת מראש
(`mailto:drasrf.clinic@gmail.com`). זה עובד בכל אחסון, גם סטטי, וללא שרת.

כדי לקבל את הפניות ישירות למייל בלי שהמבקר יצטרך תוכנת דוא״ל, הוסיפו endpoint
(למשל Formspree, Web3Forms, Netlify Forms או סקריפט משלכם) לתגית ה-`<form>`:

```html
<form class="form" data-contact data-endpoint="https://formspree.io/f/XXXXXXX" novalidate>
```

הסקריפט ישלח `POST` עם JSON בשדות: `name`, `phone`, `email`, `subject`, `message`.
בטופס כבר קיים שדה honeypot נסתר (`company`) לסינון בוטים.

## 🔗 מבנה הכתובות

הכתובות באתר נקיות, בלי סיומת `.html`:

| עמוד | כתובת |
|------|--------|
| דף הבית | `/` |
| תחומי עיסוק | `/services/` |
| אודות | `/about/` |
| צור קשר | `/contact/` |
| מדיניות פרטיות | `/privacy/` |
| הצהרת נגישות | `/accessibility/` |

זה מושג דרך **מבנה תיקיות** (`services/index.html`) ולא דרך הגדרות שרת, ולכן
הכתובות הנקיות עובדות **בכל אחסון** - Apache, nginx, Netlify, Vercel,
Cloudflare Pages, GitHub Pages ו-cPanel - בלי שום קונפיגורציה.

כל הנתיבים באתר **יחסיים**, ולכן האתר עובד גם בשורש הדומיין וגם בתת-תיקייה
(למשל בתצוגה מקדימה של GitHub Pages).

### כתובת בלי `#`

לחיצה על קישור שמוביל לסקשן בתוך העמוד (למשל "שירותי המרפאה" בתפריט, או
ניווט הקפיצה בעמוד תחומי עיסוק) **לא מוסיפה `#` לשורת הכתובת**. הגלילה מתבצעת
ב-JavaScript, והכתובת נשארת נקייה: `/` או `/services/` בלבד.

גם מי שמגיע מכתובת שמכילה עוגן (למשל קישור חיצוני ל-`/#results`) - הדף יגלול
לסקשן הנכון, והעוגן יוסר מהכתובת מיד לאחר מכן.

הפוקוס עדיין עובר לסקשן היעד, כך שקישור "דילוג לתוכן" וניווט במקלדת ממשיכים
לעבוד כרגיל.

> **הערה:** בגלל זה אי אפשר לשתף קישור ישיר לסקשן ספציפי. זו הייתה דרישה מפורשת.
> אם תרצו לאפשר זאת בעתיד - צריך להסיר את הבלוק `cleanAnchors` מ-`assets/js/main.js`.

### `.htaccess` (רק לשרתי Apache / cPanel)

הקובץ אופציונלי ומוסיף: כפיית HTTPS, הסרת `www`, הפניות 301 מכתובות `.html`
ישנות, השלמת לוכסן, דחיסה, קאשינג וכותרות אבטחה. שרתים אחרים מתעלמים ממנו.

**בנטליפיי / ורסל** אין צורך בכלום - הכתובות הנקיות עובדות מהקופסה.

- **אפס בקשות לצד שלישי** בטעינת העמוד - גופנים מאוחסנים מקומית, אין CDN, אין analytics, אין עוגיות מעקב.

## 🔗 תמונת שיתוף לרשתות (Open Graph)

הקובץ `assets/img/og-image.jpg` (1200×630) הוא מה שמופיע בתצוגה המקדימה
כששולחים קישור לאתר ב**וואטסאפ, פייסבוק, טלגרם, לינקדאין ו-X**.
הוא מכיל את התמונה של ד"ר אשרף על רקע המותג, את השם, התחום, הוותק והטלפון.

התגיות מוגדרות בכל ששת העמודים:
`og:image`, `og:image:secure_url`, `og:image:type`, `og:image:width`,
`og:image:height`, `og:image:alt`, `twitter:card`, `twitter:image`, `twitter:image:alt`.

### ⚠️ התצוגה המקדימה לא תעבוד עד שיוגדר הדומיין האמיתי

הכתובת בתגית `og:image` היא **מוחלטת** (`https://dr-atamna.co.il/assets/img/og-image.jpg`),
כי רשתות חברתיות לא יודעות לקרוא כתובות יחסיות. כל עוד הדומיין הוא מציין המקום,
וואטסאפ ופייסבוק ינסו למשוך תמונה מכתובת שלא קיימת ולא תופיע תצוגה מקדימה.
זו לא תקלה באתר - זה פשוט הדומיין. אחרי החלפתו הכול יעבוד.

### רענון המטמון אחרי שינוי

וואטסאפ ופייסבוק שומרים את התצוגה המקדימה במטמון לאורך זמן. אחרי כל שינוי
בתמונה או בכותרות צריך לרענן ידנית:

- **פייסבוק / וואטסאפ:** https://developers.facebook.com/tools/debug/ → הדביקו את הכתובת → *Scrape Again*
- **לינקדאין:** https://www.linkedin.com/post-inspector/
- **X:** https://cards-dev.twitter.com/validator

### בנייה מחדש של התמונה

אם ישתנה הטלפון, הכתובת או התמונה של ד"ר אשרף:

```bash
cd _build
python make-og-image.py
```

הטקסטים נמצאים בראש הסקריפט (`NAME`, `ROLE`, `META`, `PHONE`).
הסקריפט מוריד לבד את הגופן Assistant בהרצה הראשונה.

> דרישות: `pip install pillow pymupdf python-bidi`

## 🔍 SEO

- כותרת ותיאור ייחודיים לכל עמוד, `canonical`, Open Graph ו-Twitter Card.
- תמונת שיתוף מותגת: `assets/img/og-image.jpg` (1200×630).
- נתונים מובנים (JSON-LD): `Dentist` / `LocalBusiness` עם כתובת, טלפון, שעות ו-`hasOfferCatalog`,
  `Person` לד״ר אשרף, `WebSite`, `FAQPage` (6 שאלות), `BreadcrumbList`,
  `MedicalWebPage` + `ItemList` של 22 הטיפולים, `ContactPage`, `AboutPage`.
- `lang="he"`, `dir="rtl"`, כותרת `h1` אחת לכל עמוד והיררכיה תקינה.
- שם הרופא משולב ב-`h1` ובכותרת של דף הבית, ובכותרות של עמודי אודות וצור קשר.
- `sitemap.xml` + `robots.txt`.

### התאמה למנועי תשובות ובינה מלאכותית (AEO)

מעבר לגוגל הקלאסי, האתר מותאם גם ל-ChatGPT, Claude, Perplexity, Gemini ו-AI Overviews:

- **`robots.txt`** מאשר במפורש את כל הזחלנים של מנועי התשובות
  (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended ועוד).
  בלי אישור מפורש חלקם מדלגים על האתר, והמרפאה לא מופיעה בתשובות שלהם.
- **`llms.txt`** בשורש האתר - קובץ Markdown שמסכם למנוע ה-AI מי המרפאה, איפה היא,
  מה השעות, מה הטיפולים ומה השאלות הנפוצות. זהו הפורמט שמנועי תשובות קוראים כדי
  להבין אתר במהירות. **חשוב לעדכן אותו יחד עם כל שינוי תוכן מהותי.**
- **14 שאלות ותשובות** עם `FAQPage` schema (6 בדף הבית, 8 בעמוד תחומי עיסוק).
  תוכן בפורמט שאלה-תשובה הוא מה שמנועי AI מצטטים בפועל.
- **`knowsAbout`** ברשומת המרפאה - 21 נושאי טיפול מפורשים, כדי שהמרפאה תזוהה
  כרלוונטית לשאילתות ספציפיות ("שתל דנטלי בתל אביב", "הרמת סינוס").
- **`speakable`** - סימון הפסקאות שעוזרי קול (Siri, Google Assistant) יכולים להקריא.
- **`WebPage` + `MedicalWebPage`** מקושרים ל-`Dentist` ול-`Person`, כך שכל העמודים
  מצביעים על אותה ישות עסקית אחת.

**חשוב:** להגיש את האתר ב-HTTPS ולהגדיר את `404.html` כדף השגיאה של השרת.

תצוגה מקומית:

```bash
python -m http.server 8000
# ואז http://localhost:8000
```

## 🔧 עריכת התפריט / הפוטר בכל הדפים בבת אחת

הכותרת, התפריט הנייד, הפוטר וסט האייקונים משוכפלים בכל דף (כך אין בקשות רשת נוספות).
כדי לשנות אותם בכל הדפים בבת אחת:

1. ערכו את הבלוק הרלוונטי ב-`index.html` (הוא מקור האמת).
2. הריצו:

```bash
cd _build
python assemble.py services:services.html about:about.html contact:contact.html \
                   privacy:privacy.html accessibility:accessibility.html 404:404.html
```

הסקריפט לוקח את ה-chrome המשותף מ-`index.html`, מחבר אליו את ה-`head` וה-`main`
של כל עמוד מתוך `_build/`, ומעדכן את סימון העמוד הפעיל בתפריט (`aria-current`).

לעריכת **תוכן** של עמוד פנימי - ערכו את `_build/<page>.main.html` והריצו את הסקריפט,
או פשוט ערכו ישירות את קובץ ה-HTML הסופי (שתי הדרכים תקפות).
